## Post-Migration Tasks

### 1. Update Internal Links

Search for internal post references and update paths:

```bash
# Find all markdown files with internal links
grep -r "](/posts/" content/posts/

# Common patterns to update:
# OLD: ](/posts/Setting_up_Arch/)
# NEW: ](/posts/linux-admin/arch-linux-setup/)

# OLD: ](/posts/Single_GPU_Passthrough_Guide/)
# NEW: ](/posts/linux-admin/single-gpu-passthrough/)
```

### 2. Test Hugo Build

```bash
# From repo root
hugo server --buildDrafts

# Check for:
# - Broken links
# - Missing images
# - 404 errors in console
```

### 3. Update Navigation/Menus (if applicable)

Check if any site navigation/menu configs reference old paths:
- `config.toml` or `config.yaml`
- `layouts/partials/navigation.html`
- Any hardcoded links in templates

### 4. Setup Redirects (Optional but Recommended)

To preserve old URLs, create redirect rules:

**Using Hugo aliases in frontmatter:**

Example for `linux-admin/arch-linux-setup/part-1-swap-btrfs/index.md`:
```yaml
---
aliases:
  - /posts/Setting_up_Arch/setting_up_arch/
# ... rest of frontmatter
---
```

**Or use server-level redirects** (if using Netlify/Vercel/etc.)

### 5. Update Sitemap/RSS

Hugo should regenerate these automatically, but verify:
```bash
# After build, check:
# public/sitemap.xml
# public/index.xml
```

## Rollback Plan (If Needed)

If migration causes issues:

```bash
# Revert git changes
git checkout content/posts/

# Or restore from backup
# (Make sure to backup before migration!)
```

## Notes

- **Gradual migration:** You can migrate one category at a time if preferred
- **URL preservation:** Consider keeping old URLs active via aliases for SEO
- **Analytics:** Old URL data will be split unless you setup redirects
- **External links:** Any external sites linking to your blog will need redirects to work
